Quickstart

Use this node custom UI. Save it as content/index.html for the primary UI and open it automatically. Additional UIs such as content/control.html appear in the node drawer. 

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <link rel="stylesheet" href="./v2/nodel-webui.css" />
    <script type="module" src="./v2/nodel-webui.js"></script>
  </head>
  <body>
    <nodel-app title="YOUR BROWSER TAB TITLE" theme="dark">
      <nodel-toolbar title="YOUR TOOLBAR TITLE"></nodel-toolbar>
      <nodel-page title="YOUR NAVIGATION TAB TITLE">
        <nodel-title level="1">YOUR PAGE HEADING</nodel-title>
        <nodel-row>
          <nodel-column>
            <nodel-text>Your content goes here.</nodel-text>
          </nodel-column>
        </nodel-row>
      </nodel-page>
    </nodel-app>
  </body>
</html>

Next steps

  1. YOUR BROWSER TAB TITLE : browser tab; YOUR TOOLBAR TITLE : top-left label; YOUR NAVIGATION TAB TITLE : navigation; YOUR PAGE HEADING : visible heading. Replace the starter text.
  2. Manage files in the node editor and name additional UIs descriptively.
  3. Compose more nodel-page , nodel-row , and nodel-column elements.
  4. Component pages own examples and attribute references; Guides explain shared concepts and link back to their owning components.
  5. Copy catalogue controls and bind current-node action and signal names.
  6. Keep stable ./v2/ paths and omit the memory runtime marker. Set nodel-app theme to light when needed.

App

nodel-app is the top-level shell, theme owner, page navigation coordinator, and backdrop owner. Place one around the toolbar, page groups, optional app-global shortcuts, and footer. 

<nodel-app>
  <nodel-toolbar></nodel-toolbar>
  <nodel-page title="Home">
    <nodel-title level="1">Home</nodel-title>
  </nodel-page>
</nodel-app>

Templates

Use nodel-template with an inert native <template> to repeat controls while keeping generated children in the surrounding layout. Placeholders are replaced in text and attributes only; no script or raw HTML is evaluated.

Repeated controls

Built-in placeholders keep labels, actions, signals, and status aliases consistent across repeated controls. 

<nodel-control-grid columns="2" md="4">
  <nodel-template name="Zone" repeat="4" start="1">
    <template>
      <nodel-button join="{{item}}" variant="primary" tone="soft">
        {{name}} {{number}}
        <nodel-status-indicator signal="{{item}}Online" label="{{name}} {{number}} online"></nodel-status-indicator>
      </nodel-button>
    </template>
  </nodel-template>
</nodel-control-grid>

Fader template

Custom data-* values provide reusable placeholders, such as one action prefix shared by generated faders. 

<nodel-control-grid columns="1" md="3">
  <nodel-template name="Level" repeat="3" data-action-prefix="SetLevel">
    <template>
      <nodel-group label="{{name}} {{number}}">
        <nodel-fader action="{{actionPrefix}}{{number}}" signal="{{item}}"></nodel-fader>
      </nodel-group>
    </template>
  </nodel-template>
</nodel-control-grid>

Shared templates

Define a native template once and reference its ID from multiple nodel-template elements with independent names, ranges, and custom placeholders. 

<template id="shared-template-button">
  <nodel-button action="{{actionPrefix}}{{number}}" signal="{{item}}" variant="info" tone="outline">
    {{name}} {{number}}
  </nodel-button>
</template>
